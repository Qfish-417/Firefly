# 面试展开稿｜公文智能仿真系统

## 1. 一句话介绍

这是一个把大模型内容能力和 Word 模板排版结合起来的公文自动化系统。模型负责“理解和生成”，规则引擎负责“格式和交付”，Agent 工作流负责把多个步骤串起来并在失败时回退、校验和修正。

## 2. Agent 能力怎么讲

不要把它描述成“让大模型直接生成一个 Word”。更准确的说法是：

1. **任务规划 Agent**：根据用户动作判断是生成、润色、续写、改写还是格式修正。
2. **结构识别 Agent**：识别上传文档中的标题、主送机关、正文、附件、落款、版记等角色，只输出结构标签，不改原文。
3. **内容 Agent**：调用内网 Qwen 生成或改写正文，使用 SSE 流式返回。
4. **格式执行器**：不依赖模型输出格式，按模板规则写入字体、行距、缩进、页边距、横线、页码和分节。
5. **文档校验器**：重新读取 DOCX XML 和 PDF 坐标，检查页数、关键文字位置、横线坐标和版记页码；不通过时回退到规则修正。

## 3. 为什么要这样拆

大模型擅长语义，不擅长严格控制 Word 的浮动对象、分节、页码和分页。把格式交给模型会导致同一份内容重复导出结果不稳定。因此采用“模型做判断、代码做执行、校验器做验收”的闭环，既保留 Agent 的灵活性，又保证正式文档的确定性。

## 4. 可以主动讲的难点

- Word 预览和下载使用的排版引擎不同，不能只看浏览器效果；通过 PDF 文本坐标和 DOCX XML 属性定位真实差异。
- 浮动横线既可能重复渲染，也可能遮挡文字；通过清理 VML 备用对象、统一 DrawingML 线条和控制 `behindDoc` 解决。
- 版记必须落在下一偶数页，不能简单插入空白页；先测量正文实际页数，再按奇偶页决定是否补白。
- 上传文档中的模板内容不能直接覆盖正式模板；只提取业务内容，再用标准母版重建，避免把示例说明、占位符和错误字体带入结果。

## 5. 量化表达建议

以下数字适合在你能解释实现过程时使用：

- 支持 4 类公文模板、6 类以上正文编辑动作。
- 建立 DOCX XML、PDF 坐标和页数三层校验。
- 将一次导出问题定位从人工反复试错缩短到分钟级。
- 通过模板重建和回归样例，保证同一输入重复导出结果稳定。

不要在没有数据支撑时写“准确率 99%”“效率提升 80%”这类指标；面试中更建议强调架构取舍和问题闭环。
