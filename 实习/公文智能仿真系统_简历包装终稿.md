# 公文智能仿真系统｜Agent 驱动的公文生成与文档自动化平台

**项目角色：核心开发 / Agent 工作流设计 / 文档引擎开发**  
**项目周期：2026.06—2026.08**  
**项目形态：可部署 Web 应用，支持内网大模型与离线部署**

## 一、简历可直接使用版

面向党政机关公文起草、仿写和规范导出的智能化平台。负责从需求拆解、Agent 工作流、富文本编辑器到 DOCX/PDF 文档引擎的核心开发，将大模型的语义生成能力与确定性版式执行解耦，解决“内容生成灵活但正式公文格式必须稳定”的工程问题。

- 设计“任务规划 Agent → 内容生成/润色 Agent → 文档结构识别 → 模板渲染 → DOCX/XML/PDF 校验 → 规则修正”的闭环流程；模型负责语义和结构判断，规则引擎负责字体、行距、页边距、分页、横线、页码和分节。
- 基于 React、TypeScript、Tiptap 开发公文富文本编辑器，支持模板切换、段落级编辑、附件/版记编辑、生成结果续写与润色、实际 PDF 预览和 Word 下载。
- 基于 Spring Boot、WebFlux、SSE 和 OpenAI 兼容接口接入内网 vLLM/Qwen 模型，支持生成、改写、扩写、缩写、续写、润色和上传文档内容识别，长文本采用流式返回改善交互体验。
- 使用 Apache POI/XWPF、Jsoup、PDFBox、LibreOffice 构建 HTML → DOCX → PDF 处理链路，覆盖函、上报文、下发文、电文 4 类公文模板，自动处理标题、主送机关、正文、附件、落款、抄送、印发和页码。
- 建立 DOCX XML 属性、PDF 文本坐标、页数/奇偶页和字体映射的回归校验流程，定位并修复预览与下载格式不一致、版记跨页、偶数页补白、浮动横线遮挡和字体回退等问题。
- 使用 Docker Compose 部署 Nginx + Spring Boot + LibreOffice 预览服务，采用环境变量隔离模型地址和密钥；部署包不携带密钥，可直接复用服务器已有 AI 配置。

## 二、技术亮点

### 1. Agent 工作流

- **任务规划**：根据用户动作和文种选择生成、润色、续写、改写或格式修正流程。
- **内容 Agent**：按模板约束生成正文，输出连续段落和结构化结果，不允许生成框架字段。
- **结构识别**：对上传 Word 内容识别标题、主送、正文、附件、落款和版记等角色，保留原文语义。
- **确定性格式执行器**：按模板规则重建 Word 段落和运行，统一设置东亚字体、西文字体、字号、缩进、行距、边框、页码和分节。
- **校验与回退**：导出后再次解析 XML/PDF；若发现字体、页数、版记位置或关键文字坐标异常，执行规则化修正而不是让模型自由重排。

### 2. 预览与下载一致性

下载和实际预览使用同一份 DOCX：Word 导出接口先生成 DOCX，预览接口再由 LibreOffice 将同一 DOCX 转成 PDF。这样预览看到的分页、字体回退和版记位置与下载文件保持同源，避免浏览器 CSS 单独排版造成偏差。

### 3. 版式难点处理

- 上报文、下发文版记从正文中独立分节，按正文实际页数决定是否进入下一偶数页。
- 版记抄送行、印发行使用段落边框和右对齐制表位，避免依赖浏览器 `flex` 或浮动对象。
- 中文字体按仿宋、楷体、黑体、标题字体分别映射，数字和英文单独使用西文字体；预览容器与浏览器加载同一套免费字体资源。
- 电文保留正式母版结构，仅替换字段并注入正文，减少复杂报头、横线和页码被 HTML 重排破坏的风险。

## 五、面试时的 60 秒介绍

这是一个把大模型内容能力和 Word 正式排版结合起来的公文自动化系统。我的核心设计不是让模型直接生成 Word，而是让模型负责理解素材、生成正文和识别文档结构，再由确定性规则引擎负责模板、字体、行距、分页和页码，最后用 DOCX XML 和 PDF 坐标做自动验收。这样既能保留 Agent 对自然语言任务的适应能力，又能保证正式公文导出结果稳定。项目中我重点解决了浏览器预览和下载 Word 排版不一致、上报文/下发文版记必须落在下一偶数页、以及中文字体回退导致字形变化等问题。

## 六、可能被追问的问题

**问：为什么不让大模型直接输出完整 Word？**  
答：模型擅长语义，不擅长稳定控制 Word 的分节、浮动对象、字体范围和分页。把版式交给模型会导致同一输入多次导出不一致，因此采用“模型判断、代码执行、校验器验收”的闭环。

**问：Agent 体现在哪里？**  
答：体现在任务规划、内容生成、结构识别、格式执行和校验回退的多步骤协同。每一步都有明确输入输出和失败处理，不是单次 Prompt 调用。

**问：预览为什么能和下载保持一致？**  
答：预览接口复用下载接口生成的同一份 DOCX，再由 LibreOffice 转 PDF；不再用浏览器 CSS 重新模拟 Word 分页。

**问：如何保证字体一致？**  
答：DOCX 中分别声明仿宋、楷体、黑体、标题字体和 Times New Roman；预览容器通过 fontconfig 将这些名称分别映射到对应免费字体，浏览器也加载同一套字体文件。

**问：如何保护远程 AI Key？**  
答：部署包不包含 `.env`；容器通过环境变量读取服务器已有配置，替换版本时先备份并校验远程 `.env`，避免把本地开发配置带到生产环境。
