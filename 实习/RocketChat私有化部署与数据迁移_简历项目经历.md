# Rocket.Chat 私有化部署与跨版本数据迁移｜DevOps / 容器化运维

**项目角色：运维开发（实习）**　　**项目周期：2026.07—2026.08**

## 项目简介

面向教育系统的 Rocket.Chat 私有化即时通讯平台部署与历史数据迁移项目。将运行多年的 Rocket.Chat 3.18.2 生产数据无损迁移至 6.13.0，并部署到新的多服务器集群（应用服务器与数据库服务器分离），通过 Docker、MongoDB 副本集、Nginx 反向代理与统一 SSL 证书体系实现内网私有化访问。

## 核心工作

- 设计并执行 Rocket.Chat 3.18.2 → 4.8.7 → 5.4.10 → 6.13.0 的跨大版本分级迁移链，将数据库迁移版本从 232 安全推进至 304，全程未篡改迁移版本号，迁移 130 万+ 文档零失败。
- 部署 MongoDB 5.0/6.0 单节点副本集（rs0），定位并解决副本集成员地址使用回环地址（127.0.0.1）导致的驱动连接失败；完成 MongoDB 5.0 → 6.0 的 featureCompatibilityVersion 升级。
- 基于 Docker 实现完全离线部署：使用 docker save/load 生成并分发镜像包；对 23GB 数据库快照采用 rsync 断点续传与分片传输，解决 ZMODEM 4GB 上限与网络中断导致的传输失败。
- 使用 Nginx 配置反向代理与 HTTPS，安装并校验通配证书（*.nbsedu.com.cn）证书链（openssl 校验叶子/中间/根证书顺序与域名覆盖），配置 WebSocket 升级头以支持 Rocket.Chat 实时通信。
- 排查并解决 10+ 项部署与网络问题：Rocket.Chat 子路径部署的资源前缀缺失导致页面白屏、moment locale 语言包缺失（zh.js）、Service Worker 注册作用域错误、CORS 跨域拦截、WebSocket 101 后持续重连、WAF/零信任网关对静态资源与长连接的拦截等。
- 建立分层验证方法论：使用 curl / openssl / nc / telnet / ss 等工具，从端口连通性、TLS 证书链、API 响应耗时、WebSocket 状态等维度逐层诊断，快速将问题定位到应用层 / 反向代理层 / 网关层 / 网络层。

## 项目结果

- 完成 Rocket.Chat 6.13.0 + MongoDB 6.0 的多服务器私有化部署，130 万+ 历史数据（6.3 万用户、6.5 万房间、66 万消息）完整迁移，失败数为 0。
- 将服务器侧配置（Nginx、证书、应用地址、WebSocket）全部就绪，并与网络侧（WAF / 零信任网关 / 安全组 / 端口映射）问题清晰分离，形成可复用的“服务器侧 vs 网络侧”排查思路。
- 产出可离线部署的镜像包与迁移 / 部署脚本，降低后续环境复制的成本。
